02 / Bottom layer

Build a task model that stands on its own.

Initialize the stack and name the first branch task-model. This layer owns task creation and completion—no HTTP, no HTML.

$ gh stack init
# When prompted, enter: task-model
$ node -e "for (const dir of ['src','test']) require('fs').mkdirSync(dir, { recursive: true })"

Create src/tasks.js

export function createTaskStore() {
const tasks = [];

return {
all: () => [...tasks],
add(title) {
const cleanTitle = title?.trim();
if (!cleanTitle) throw new Error("A task title is required");
const task = { id: crypto.randomUUID(), title: cleanTitle, done: false };
tasks.push(task);
return task;
},
complete(id) {
const task = tasks.find((item) => item.id === id);
if (!task) throw new Error("Task not found");
task.done = true;
return task;
}
};
}

Create test/tasks.test.js

import test from "node:test";
import assert from "node:assert/strict";
import { createTaskStore } from "../src/tasks.js";

test("adds and completes a task", () => {
const store = createTaskStore();
const task = store.add("Review the stack");
assert.equal(store.all().length, 1);
assert.equal(store.complete(task.id).done, true);
});

test("rejects an empty title", () => {
const store = createTaskStore();
assert.throws(() => store.add(" "), /title is required/);
});
$ npm pkg set type="module"
$ npm test
$ git add package.json src test
$ git commit -m "Add tested task model"
Layer contract

Two tests pass. A reviewer sees only the domain behavior and its tests. This pull request will target main.

03 / Middle layer

Expose the model through HTTP.

Create a branch on top of task-model. The API consumes the model below it and adds two routes: list tasks and create a task.

$ gh stack add task-api

Create server.js

import { createServer } from "node:http";
import { createTaskStore } from "./src/tasks.js";

const store = createTaskStore();
store.add("Review the model pull request");

export const server = createServer(async (request, response) => {
response.setHeader("content-type", "application/json");

if (request.method === "GET" && request.url === "/api/tasks") {
return response.end(JSON.stringify(store.all()));
}

if (request.method === "POST" && request.url === "/api/tasks") {
let body = "";
for await (const chunk of request) body += chunk;
try {
const task = store.add(JSON.parse(body).title);
response.writeHead(201);
return response.end(JSON.stringify(task));
} catch (error) {
response.writeHead(400);
return response.end(JSON.stringify({ error: error.message }));
}
}

response.writeHead(404);
response.end(JSON.stringify({ error: "Not found" }));
});

if (process.env.NODE_ENV !== "test") {
server.listen(3000, () => console.log("Task API: http://localhost:3000"));
}
$ npm test
$ node server.js
# In another terminal:
$ curl http://localhost:3000/api/tasks
$ curl -X POST http://localhost:3000/api/tasks -H "content-type: application/json" -d '{"title":"Ship a small PR"}'
$ git add server.js
$ git commit -m "Expose tasks over HTTP"
Layer contract

The original model tests still pass, GET returns a task array, and POST returns 201. This pull request will target task-model.

04 / Top layer

Put a browser interface on the API.

The final layer changes the server only enough to serve a static interface. A reviewer can focus on the user flow without re-reviewing model internals.

$ gh stack add task-ui
$ node -e "require('fs').mkdirSync('public', { recursive: true })"

Add this block near the top of server.js

import { readFile } from "node:fs/promises";

// Add inside createServer, before the API routes:
if (request.method === "GET" && request.url === "/") {
response.setHeader("content-type", "text/html");
return response.end(await readFile("public/index.html", "utf8"));
}

Inspect the local shape first, then let the extension push every branch and create pull requests with the correct bases.

task-modeltargets main
$ gh stack view

$ gh stack view
Expected result

GitHub shows three linked pull requests. Opening any one displays the stack map, and its Files changed tab contains only that layer’s diff.

Team handoff: A teammate can run gh stack checkout and choose the remote stack, or use a pull request number such as gh stack checkout 42.

06 / Land it

Review what each person is qualified to judge.

Domain reviewer

Opens task-model. Checks validation, state behavior, and tests.

API reviewer

Opens task-api. Checks status codes, request parsing, and errors.

Product reviewer

Opens task-ui. Checks the end-to-end task creation flow.

Approve each focused pull request. To land everything together, merge the top ready pull request from its stack controls. To land only the foundation, merge task-model; GitHub keeps the upper pull requests open and retargets them.

# After main or a lower layer changes:
$ gh stack sync
# Fetches, rebases, pushes, and refreshes PR state.

# After the stack is merged:
$ gh stack sync --prune
Compare the review jobs

Imagine the model, HTTP handling, and interface as one pull request. Which reviewer would confidently approve all three concerns? The stack did not reduce the work—it gave each decision a clear boundary.

Recovery playbook

Stacks are normal Git—with guardrails.

Trunk moved

Rebase every layer from the bottom upward.

gh stack rebase
Conflict paused rebase

Fix files, stage them, and continue—or restore the pre-rebase state.

git add .
gh stack rebase --continue
gh stack rebase --abort
Branch needs reordering

Open the interactive stack editor to reorder, rename, fold, or drop layers.

gh stack modify
Push was rejected

Synchronize against the latest remote stack and retry.

gh stack sync
gh stack submit
