Build one stack.
Feel the difference.

This is a small, local exercise: take a feature with three logical layers, create the stack, and see why every reviewer gets a better job.

~30 MINUTESGITHUB CLIA SCRATCH REPOSITORY

Your route

01Install the extension 02Create the foundation 03Add the layers 04Review and merge
01 / Get the tool

Install the stack extension.

Stacked pull requests are available on GitHub; the CLI extension is the quickest way to build your first one from the terminal.

$ gh extension install github/gh-stack

Use a scratch repository if you want a no-stakes first run. You will still use your ordinary GitHub authentication.

02 / First layer

Make the smallest complete foundation.

Start from main, make a focused change, then create the first branch and pull request. This is the lowest layer of the stack.

$ git switch -c data-model
# make your focused change
$ git push -u origin data-model
03 / Build upward

Put the next concern on top.

After opening the first pull request, create the next branch from it. Its pull request targets the layer below instead of main. Repeat for your UI, integration, or final behavior.

data-modeltargets main
api-endpointtargets data-model
preference-uitargets api-endpoint

The exact changes are yours. The important part is that each layer is independently understandable and its pull request targets the previous layer.

04 / Let the stack work

Review in layers. Merge with intent.

Reviewers can inspect a single layer’s diff and work in parallel. When a ready layer is merged, every layer above it remains open and is automatically rebased and retargeted. Merge the latest ready pull request to land it and all unmerged layers below it in one operation.
